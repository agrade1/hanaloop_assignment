# 과제 요구사항 정리

## 1. 과제 개요

본 과제는 과제용 데이터를 활용하여 제품 탄소발자국, 즉 PCF(Product Carbon Footprint) 전과정 데이터를 시각화하는 인터랙티브 대시보드를 구현하는 것이다.

과제의 핵심은 탄소 도메인을 빠르게 이해하고, 실제 동작하는 UI를 설계·구현·설명할 수 있는지를 보여주는 것이다.

## 2. 회사/서비스 도메인 이해

해당 회사는 기업 고객이 원소재, 전기, 운송 등의 데이터를 입력하면 제품별 탄소발자국을 자동 계산할 수 있는 SaaS 플랫폼을 개발한다.

따라서 이번 과제에서는 단순한 차트 UI가 아니라, 다음 흐름이 보이도록 구현하는 것이 중요하다.

1. 제품별 활동 데이터 확인
2. 활동량과 배출계수를 기반으로 탄소배출량 계산
3. 제품별 총 PCF 확인
4. 생애주기 단계별 배출 비중 확인
5. 배출량이 높은 원인 파악
6. 감축 시나리오를 통한 예상 절감 효과 확인

## 3. 대상 사용자

과제에서 명시한 대상 사용자는 실무자와 경영자이다.

### 경영자 관점

경영자는 전체 배출량 현황과 주요 리스크를 빠르게 파악해야 한다.

필요한 정보는 다음과 같다.

- 전체 제품의 총 PCF
- 평균 PCF
- 배출량이 가장 높은 제품
- 주요 배출 원인
- 감축 시나리오에 따른 예상 절감 효과

### 실무자 관점

실무자는 제품별 세부 데이터를 확인하고, 어떤 단계에서 배출량이 많이 발생하는지 분석해야 한다.

필요한 정보는 다음과 같다.

- 제품별 활동 데이터
- 원소재, 전기, 운송 등 생애주기 단계별 배출량
- 활동량, 단위, 배출계수, 계산된 배출량
- 제품/단계별 필터링
- 상세 테이블 기반 데이터 확인

## 4. 구현 목표

이번 과제의 목표는 완전한 탄소회계 시스템을 구현하는 것이 아니라, 과제용 데이터를 기반으로 PCF 계산 흐름과 시각화 구조를 보여주는 MVP 대시보드를 구현하는 것이다.

구현 목표는 다음과 같다.

- Next.js와 TypeScript 기반 프로젝트 구성
- 과제용 데이터를 기반으로 제품별 PCF 계산
- 원소재, 전기, 운송 등 생애주기 단계별 배출량 시각화
- 실무자와 경영자 모두가 이해할 수 있는 대시보드 구성
- 제품 선택, 단계 필터, 감축 시나리오 등 인터랙션 구현
- README와 AI 사용 내역 문서화

## 5. 계산 기준

본 과제에서는 PCF 계산을 단순화하여 다음 방식으로 처리한다.

```txt
배출량 = 활동량 × 배출계수
제품별 총 PCF = 해당 제품의 모든 생애주기 단계 배출량 합계
```

## 6. 데이터 입력 UI 범위

본 과제에서 사용자가 직접 값을 입력하는 화면은 다음 두 가지로 한정한다.

1. **엑셀 업로드 화면** — 과제용 데이터(엑셀)을 업로드하여 시각화 대상 데이터로 사용한다. 잘못된 형식, 누락된 컬럼, 잘못된 값 등에 대해 에러 메시지를 표시한다.
2. **감축 시나리오 입력** — 사용자가 특정 생애주기 단계의 감축률(%) 또는 대체 옵션을 입력하여 예상 절감 효과를 시뮬레이션할 수 있도록 한다.

제품·활동 데이터의 직접 추가/편집(CRUD) 화면은 MVP 범위에 포함하지 않는다. 시간이 남는 경우 후속 확장으로 검토한다.

## 7. 지원자 체크리스트

과제 제출 시 평가되는 항목을 본 문서에 함께 정리해두어 구현 중 누락을 방지한다.

### 필수

- PCF 계산 결과가 시각화되어 있으며, 사용자가 직관적으로 이해할 수 있고 의미가 명확하게 전달된다.
- 표시되는 데이터 값이 정확하고 단위 등 표시가 적절히 되어 있다.
- 데이터 입력 화면에서 오류 입력 시 에러 메시지가 표시된다.
- UI 실행 과정을 비디오 캡쳐와 스크린샷으로 안내한다.
- README에 로컬 실행 방법이 5단계 이내로 명확하게 작성되어 있다. `yarn start`로 오류 없이 실행된다.
- README에 AI 도구 사용 내역이 기록되어 있다.
- README에 시스템 전체적인 설명과 설계 내용을 포함한다.
- GitHub 저장소가 public이고 커밋 히스토리가 있다.

### 권장

- ERD 또는 스키마 다이어그램이 README에 포함되어 있다.
- 발표에서 "왜 이렇게 설계했는가"를 2개 이상 설명할 수 있다.
- 설계 trade-off를 1개 이상 말할 수 있다.

### 보너스

- Docker Compose로 즉시 실행 가능하다.
- 과제용 엑셀 데이터를 그대로 임포트할 수 있다.
- OpenAPI/Swagger 문서가 있다.
- 타 시스템과 비교한다.

본 MVP에서는 필수와 권장을 우선 충족시킨 뒤, 시간이 남는 범위 내에서 보너스 항목 중 "엑셀 PostgreSQL 임포트"와 "Docker Compose"를 함께 시도한다.
